# 离线中间结果兼容方案

“离线工具输出中间解析结果”的方案继续保留，但它不是 Java 主系统保存历史状态的机制。

建议让离线工具输出与 `/api/import` 相同的文档包：每份记录包含 `filename`、`line` 和 `content`，其中 `content` 使用 V6 标准 JSON 或已支持的旧格式 JSON。Java 的 `ImportFile` 是这条边界的内部 DTO。这样将来可以增加文件包适配器，而不修改图算法、存储和查询层。

离线工具如果不能保存历史状态，有两种使用方式：

1. 首次迁移时让工具读取完整源文件集合并输出一次完整包；
2. Java 服务投入使用后，让工具只解析本次新增或更新的源文件，由 Java 数据库保存历史。

第二种方式下，第二次不需要附带第一次的文件。只有在 Java 数据库丢失、重建或切换到一个全新的空库时，才需要重新提交完整有效集合。

当前 Java 服务直接接收原始 V6 JSON，因此离线工具不是运行依赖。后续若固定一种独立中间格式，应先为其增加 schema、版本号、摘要、条线、文档身份和兼容性测试，再增加适配器。
